# spacing-map

Builds and applies the Sinhala **spacing scheme**: a YAML map of sidebearing
relationships derived from the design-stages model, ultimately written into
`.glyphspackage` sources as Glyphs metrics keys.

The model (`model/sinhala-design-dependencies.yaml`) already
treats spacing as inheritance — the first-designed member of a spacing class
(its `rep`) sets the sidebearing, every later member inherits it. This tool
makes that operational:

```
design-stages model          sinhala-spacing.yaml            .glyphspackage
(spacing_classes +   ───►    (relationships + unit    ───►   (leftMetricsKey /
 per-glyph spacing)  build    values + exceptions)    apply    rightMetricsKey)
                     -map
```

## Setup

```sh
cd tools/spacing-map
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Usage

```sh
# seed or refresh ../../model/sinhala-spacing.yaml from the design-stages model
./venv/bin/python -m spacing_map build-map

# validate + preview the diff without writing
./venv/bin/python -m spacing_map build-map --check

# measure a font against the scheme (read-only)
./venv/bin/python -m spacing_map audit --font path/to/Font.glyphspackage

# every class and member, not just drift; wider drift tolerance
./venv/bin/python -m spacing_map audit --font Font.glyphspackage -v --tolerance 12

# harvest a well-spaced font's class values as candidate scheme numbers
./venv/bin/python -m spacing_map audit --font Font.glyphspackage \
    --master Regular --emit-values values-fontname.yaml
```

## The scheme file (`model/sinhala-spacing.yaml`)

```yaml
meta:        # generator info, model version, counts
classes:
  right:
    R-bowl:
      rep: ට                      # sets the sidebearing
      members: [ට, ච, ධ, ...]     # inherit it (core members + every glyph
                                  #   whose spacing: field declares the class,
                                  #   e.g. composites like ආ)
      value: 1.0                  # rep's target sidebearing as a multiple of
                                  #   the font's spacing_unit metric
                                  #   (null = not yet authored)
  left:
    L-tta: {rep: ට, members: [...], value: 1.0}
forms:       # fused form-family glyphs (ටි ම් කු …), grouped by family;
             # each maps to a left/right class. Resolution: per-form
             # form_overrides > family form_spacing > inherited from the
             # host (the form's first character). Only families marked
             # `fused: true` in the model expand here.
  u-special:
    note: ...                     # the family's spacing_note (flags)
    glyphs:
      කු: {left: L-ka, right: R-u}
exceptions:  # bespoke-spaced glyphs, per the model's do_not rule:
             #   ය: {right: {reason: "..."}}
unassigned:  # spacing-carrying chars with no class on a side (workbench pool)
nonspacing:  # zero-advance combining marks (ි ී ් ු ූ) — never spaced
flags:       # per-glyph spacing_note markers from the model: provisional
             # class guesses awaiting the designer (gap rare-spacing-provisional)
```

### Division of truth

| data | source of truth | on `build-map` refresh |
|---|---|---|
| classes, reps, members | design-stages model | rebuilt (diffs reported) |
| `forms`, `flags`, `nonspacing` | design-stages model | rebuilt |
| `value`, `note`, extra keys | this file | preserved |
| `exceptions` | this file | preserved |
| `unassigned` | computed | regenerated |

Values are font-agnostic: a per-font values file (planned, workbench-exported)
supplies `spacing_unit` in font units plus any per-class overrides.

Seeding: classes whose rep is ට start at `value: 1.0` because the model
defines `spacing_unit` as ට's sidebearing rhythm; everything else starts
`null` until authored.

## Validation

`build-map` refuses to write on model errors: a rep missing from its own
members, a character core-listed in two classes on the same side, a
per-glyph `spacing:` declaration that contradicts core membership or names an
unknown class, a form generated by two families, a form whose host has no
class on a side, or a `form_spacing`/`form_overrides` entry naming an unknown
class. Warnings (membership without a matching per-glyph declaration,
members with no model entry, overrides for unknown forms) are printed but
don't block.

## `audit` — measuring a font against the scheme

Read-only. Answers three questions per master:

| | |
|---|---|
| **coverage** | which scheme entries the font actually contains |
| **drift** | does each member's measured sidebearing match its class rep's? (the design gate "every new glyph sits correctly in its spacing class", measured rather than eyeballed) |
| **keys** | does each member carry a metrics key pointing at its rep — i.e. is the inheritance wired up in the source, or only true by coincidence? |

Sidebearings are not stored in a Glyphs source; only each layer's `width` is.
LSB/RSB are derived from outline bounds exactly as Glyphs displays them
(`LSB = bounds.x`, `RSB = width − (bounds.x + bounds.width)`), with components
resolved, so composites measure correctly.

It also reports the font's **implied spacing unit** — the sidebearings of ට,
the glyph the model says defines the unit — and each class rep's sidebearing as
a multiple of it. `--emit-values` writes those multiples to a values file, which
turns a well-spaced existing font into candidate `value:` numbers for the
scheme. They are measurements, not endorsements: review before copying in.

### Glyph-name resolution

Single characters resolve **by codepoint** straight from the font — exact and
naming-agnostic. Fused forms (ටි, කු, ක්, ද්‍රි) have no codepoint and must be
resolved **by name**, which is a per-vendor convention. `names.py` encodes the
lanka-glyphsets one (also used by `tools/composite-map`):

| form | name | rule |
|---|---|---|
| ක | `ka-sinh` | stem + inherent `a` |
| ක් | `k-sinh` | stem alone (al-form) |
| කි ‍/ කී | `kI-sinh` / `kIi-sinh` | stem + sign suffix (`I Ii U Uu Ae Aae`) |
| ක්‍ර | `kRa-sinh` | stem + `R` + inherent `a` |
| ක්‍රි | `kRI-sinh` | stem + `R` + sign suffix |
| න්‍ද | `nDa-sinh` | stems joined, later ones capitalised |

Stems come from the font's own name for each codepoint where possible, so a
font naming ඦ `nyja-sinh` resolves ඦි to `nyjI-sinh` without any table — this
also covers letters missing from the vendored lanka-glyphsets data (ඦ is).

On AbhayaLibre 126 of 128 fused forms resolve; the two that don't (ඳ්‍රි ඳ්‍රී)
are genuinely absent from the font. On Noto Sans Sinhala only 59 resolve — not
a naming mismatch (Noto uses the same convention: `ka-sinh`, `ttha-sinh`) but a
**fusion-policy** difference: Noto positions ි with nine contextual
`isign-sinh.altN` alternates instead of fusing it into a single glyph. Coverage
therefore measures how far a font follows the model's `fused: true` families.

Failures are always reported as absent, never silently skipped. For a font
that does name things differently, `--names <yaml>` maps entries by hand:

```yaml
ඨි: ThI-sinh
ඨී: ThIi-sinh
```

## `export-js` — data for the spacing workbench

```sh
./venv/bin/python -m spacing_map export-js          # write tools/_generated/sinhala-spacing.js
./venv/bin/python -m spacing_map export-js --check  # fail if it is stale
```

Run it after every change to `sinhala-spacing.yaml`. The browser tool that
authors values and previews the scheme on a font is
[`tools/spacing-workbench`](../spacing-workbench/).

## Glyphs plugin

[`glyphs-plugin/`](glyphs-plugin/) packages the scheme as a Glyphs 3 plugin
that writes the metrics keys live in the open font: automatically onto newly
added glyphs (toggle, on by default), or across the whole font on demand.
Existing keys are never overwritten; ones that disagree with the map are
flagged. The key decisions live in `spacing_map/keyplan.py`, shared with this
CLI and vendored into the bundle by:

```sh
./venv/bin/python -m spacing_map build-plugin          # refresh the bundled scheme + code
./venv/bin/python -m spacing_map build-plugin --check  # fail if it is stale
```

Run it after every change to `sinhala-spacing.yaml`, as with `export-js`.

## Roadmap
