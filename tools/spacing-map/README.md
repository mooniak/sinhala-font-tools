# spacing-map

Builds and applies the Sinhala **spacing scheme**: a YAML map of sidebearing
relationships derived from the design-stages model, ultimately written into
`.glyphspackage` sources as Glyphs metrics keys.

The model (`sinhala-design-stages/sinhala-design-dependencies.yaml`) already
treats spacing as inheritance — the first-designed member of a spacing class
(its `rep`) sets the sidebearing, every later member inherits it. This tool
makes that operational:

```
design-stages model          sinhala-spacing.yaml            .glyphspackage
(spacing_classes +   ───►    (relationships + unit    ───►   (leftMetricsKey /
 per-glyph spacing)  build    values + exceptions)    apply    rightMetricsKey)
                     -map
```

## Setup

```sh
cd tools/spacing-map
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Usage

```sh
# seed or refresh ../../sinhala-spacing.yaml from the design-stages model
./venv/bin/python -m spacing_map build-map

# validate + preview the diff without writing
./venv/bin/python -m spacing_map build-map --check
```

## The scheme file (`sinhala-spacing.yaml`, repo root)

```yaml
meta:        # generator info, model version, counts
classes:
  right:
    R-bowl:
      rep: ට                      # sets the sidebearing
      members: [ට, ච, ධ, ...]     # inherit it (core members + every glyph
                                  #   whose spacing: field declares the class,
                                  #   e.g. composites like ආ)
      value: 1.0                  # rep's target sidebearing as a multiple of
                                  #   the font's spacing_unit metric
                                  #   (null = not yet authored)
  left:
    L-tta: {rep: ට, members: [...], value: 1.0}
forms:       # fused form-family glyphs (ටි ම් කු …), grouped by family;
             # each maps to a left/right class. Resolution: per-form
             # form_overrides > family form_spacing > inherited from the
             # host (the form's first character). Only families marked
             # `fused: true` in the model expand here.
  u-special:
    note: ...                     # the family's spacing_note (flags)
    glyphs:
      කු: {left: L-ka, right: R-u}
exceptions:  # bespoke-spaced glyphs, per the model's do_not rule:
             #   ය: {right: {reason: "..."}}
unassigned:  # spacing-carrying chars with no class on a side (workbench pool)
nonspacing:  # zero-advance combining marks (ි ී ් ු ූ) — never spaced
flags:       # per-glyph spacing_note markers from the model: provisional
             # class guesses awaiting the designer (gap rare-spacing-provisional)
```

### Division of truth

| data | source of truth | on `build-map` refresh |
|---|---|---|
| classes, reps, members | design-stages model | rebuilt (diffs reported) |
| `forms`, `flags`, `nonspacing` | design-stages model | rebuilt |
| `value`, `note`, extra keys | this file | preserved |
| `exceptions` | this file | preserved |
| `unassigned` | computed | regenerated |

Values are font-agnostic: a per-font values file (planned, workbench-exported)
supplies `spacing_unit` in font units plus any per-class overrides.

Seeding: classes whose rep is ට start at `value: 1.0` because the model
defines `spacing_unit` as ට's sidebearing rhythm; everything else starts
`null` until authored.

## Validation

`build-map` refuses to write on model errors: a rep missing from its own
members, a character core-listed in two classes on the same side, a
per-glyph `spacing:` declaration that contradicts core membership or names an
unknown class, a form generated by two families, a form whose host has no
class on a side, or a `form_spacing`/`form_overrides` entry naming an unknown
class. Warnings (membership without a matching per-glyph declaration,
members with no model entry, overrides for unknown forms) are printed but
don't block.

## Roadmap

- `audit --font <pkg>` — measure actual member LSB/RSB vs rep and rep vs
  `value × spacing_unit`; report drift, missing keys, unflagged bespokes.
- `apply --font <pkg> [--apply]` — write `leftMetricsKey`/`rightMetricsKey`
  on member glyphs (dry-run by default, surgical per-glyph-file writes as in
  `tools/composite-map/composite_map/packageio.py`).
- `export-js` — vendored `tools/_generated/sinhala-spacing.js` for the
  spacing workbench (browser authoring/preview tool).

Like `tools/composite-map`, glyph naming is currently hardcoded to the
lanka-glyphsets convention (chars in the scheme, `name-sinh` at apply time).
